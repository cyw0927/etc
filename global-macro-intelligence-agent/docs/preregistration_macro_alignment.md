# 거시 연구모델 발행 보완 사전 등록: 입력 기준 시각 일치와 FRED 최신성 규칙

- 작성: 2026-10-30. **발행 코드를 바꾸기 전**에 이 문서를 별도 커밋한다. 커밋 시각이 등록 시점이다.
- 대상: `preregistration_macro_forward.md`(`81a1d50`, 가족 `macro_lag2d_fixed_v1`)와 `preregistration_release_checked.md`(`c726a91`, 가족 `macro_release_checked_v1`).
- 모델(`b0813…568c`), 라벨(SPY 5 NYSE 세션), 장부 위치와 append-only 규칙, Brier 기술통계만 허용한다는 원칙은 **그대로 유지**한다.

## 1. 바꾸는 이유 (이미 알고 있는 것)
- 2026-10-30 독립 검토에서 다음 불일치를 확인했다.
  - 학습(`train_alfred_research.py`, `alfred_research_features.py`)은 각 행의 결정 시각을 **기준 세션 마감 + 15분**으로 두고, 그 UTC 날짜에서 2일 전까지의 ALFRED 수정본만 쓴다.
  - 실제 발행(`issue_macro_forward.py`, `issue_release_checked.py`)은 **발행 시점의 벽시계 시각**으로 같은 계산을 한다.
  - 그래서 기준 세션 마감 다음 UTC 날짜에 발행하면, 학습 때는 볼 수 없던 하루치 수정본이 입력에 들어갈 수 있다. 발행 시각을 자정 전후로 고르는 것만으로 입력이 바뀐다.
- 실제 사례:
  - `macro_release_checked_v1`의 유일한 기록(기준일 2026-10-28, 발행 10-29 02:10 UTC)은 M2 9월값(10-27 수정본, p = 0.595570)을 썼다.
  - 학습 정의를 적용하면 같은 기준일에 M2 8월값을 쓰고 p = 0.595082가 된다.
- `macro_lag2d_fixed_v1`의 유일한 기록(기준일 2026-10-27)은 두 정의에서 네 지표 모두 같은 관측값을 고른다. 독립 검토의 재계산과 같다.
- FRED 페이지 최신성 조건이 사전 등록(36시간)과 다르다.
  - 코드는 `ac68504`(2026-10-29 02:14:31 UTC 커밋)에서 15분으로 강화됐는데, 사전 등록 문서는 바뀌지 않았다.
  - 유일한 기록은 그 4분 전(02:10:15 UTC)에 36시간 규칙으로 발행됐다(요청 시작 후 21.6분).
- 등록 시점에 두 가족의 채점 행은 0개다. 이 보완은 성과 결과를 보고 정한 것이 아니다.

## 2. 규칙
1. **입력 기준 시각:** 두 가족 모두 이 문서 커밋 이후의 발행부터, 거시 입력의 기준 시각을 **기준 세션의 NYSE 정규장 마감 + 15분**(학습과 같은 정의)으로 한다. 그 UTC 날짜에서 2일 전 이하인 수정일·관측일만 쓴다. 발행 시점의 벽시계 시각은 입력 선택에 쓰지 않는다. 발행 시각에 관한 다른 조건(수집 36시간 이내, 다음 개장 전, UTC 날짜 변경 시 차단 등)은 그대로 둔다.
2. **결과:** 같은 기준일에 대해서는 언제 발행하든 같은 입력이 선택된다. `macro_release_checked_v1`는 고정 증거(관측월 2026-09, 정해진 발표일)가 이 기준으로 모두 포함되는 기준일부터만 발행된다. M2 발표(10-27)를 고려하면 기준일 2026-10-29 이후다. 증거가 맞지 않으면 v1 규칙대로 발행을 차단한다.
3. **FRED 페이지 최신성:** `macro_release_checked_v1`의 FRED 페이지 요청 시작은 발행 결정 시각으로부터 **15분 이내**여야 한다. 이 조건은 `ac68504` 커밋 시각(2026-10-29 02:14:31 UTC) 이후 발행분에 적용한다. 그 전 기록은 사전 등록의 36시간 조건으로 발행됐다.
4. **기존 기록:** 두 기록 모두 append-only이므로 수정·삭제하지 않는다.
   - `macro_release_checked_v1`의 2026-10-28 기록은 '기준 시각 보완 이전 정의로 발행됨'으로 문서에 표시한다.
   - 이후 이 가족의 기술통계를 낼 때는 보완 이후 발행분과 **분리해서** 보고한다.
5. 발행 기록(manifest)에 입력 기준 시각, 그 정의, 이 문서의 커밋을 남긴다.

## 3. 확인할 테스트
- 같은 기준일에 대해 발행 시각이 UTC 자정 전이든 후든 같은 입력이 선택된다
- 입력 기준 시각이 기준 세션 마감 + 15분과 같다(학습 정의와 동일)
- `macro_release_checked_v1`가 M2 9월값을 요구할 때 기준일 2026-10-28은 차단되고 2026-10-29는 통과한다
