# v0.5 기준 예측의 안전한 발행과 한계

## 현재 동작

별도 사전등록 `preregistration_v0.5_pit_baseline.md`에 따라 SPY, QQQ, GLD(GOLD), KOSPI, NIKKEI의 5·20거래일 과거 상승비율만 계산한다. 외부시장·거시·금리·거래량 자료는 사용하지 않는다. 자산별 정규장 실제 마감과 휴장일, 일광절약시간, 다음 장 개장 이전 및 수집 시작·스냅샷 완료 시각을 검사한다. 최근 거래일 누락이나 스냅샷 해시 불일치가 발생하면 해당 자산을 차단하고, 과거 학습구간에 빠진 거래일이 있으면 해당 구간의 라벨을 제외한다. 이는 예측력이 증명된 모델이 아니다.

BTC는 수집본의 2026-10-27 봉이 누락됐고, Yahoo의 BTC·FX 일봉 경계와 WTI 연속선물의 봉·롤 규칙을 증명할 공급자 계약이 없다. 따라서 BTC, USDKRW, USDJPY, WTI는 발행이 차단된다. 종가 확정에 적용한 15분은 보수적인 운영 가정이며 공급자 갱신 완료 또는 수정종가의 불변성을 보증하지 않는다. 거래소 달력도 공급자 원본 봉의 정의를 독립적으로 증명하지 않는다.

발표·수집 시각과 수정 빈티지를 구분하는 `src/gmia/data/availability_v05.py`는 엄격한 시간 계약의 시작점이며 FRED/ALFRED 수집 및 기존 특징 생성기에 연결되지 않았다. 기존 15후보는 발표시각·과거 빈티지와 시차 정합성 문제가 해결된 것으로 간주하지 않는다. 과거 가격은 발행 시점의 스냅샷이며 과거 각 시점에 그 버전이 알려져 있었다는 증거가 아니다. 새 장부의 자동 만기 채점은 아직 구현되지 않았다.

## 사용

프로젝트 가상환경에서 `requirements-operations.txt` 의존성을 설치한 뒤, 기존 수집본에 대해 아래 명령을 실행한다. 이 명령은 발행하지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts/issue_pit_baseline.py --batch data/operations/collections/<수집본_ID>
```

동일 명령 끝에 `--issue`를 붙이면 통과한 예측만 `data/operations/issuance/ledger.sqlite3`에 원자적으로 기록한다. 기존 `data/ledger/forward.sqlite3`, raw 자료 및 백업은 건드리지 않는다. 발행 후 동일 예측은 중복을 무시하며, 같은 키에 서로 다른 확률 또는 스냅샷이 있으면 전체 발행을 취소한다. 이 별도 장부도 개인 데이터를 보관하는 로컬 자산으로 취급하고 외부에 올리지 않는다. SQLite 트리거는 실수로 인한 수정·삭제 방지 장치이며 저장소 관리자에 대한 불변 저장 보장은 아니다. 운영 백업과 복구 확인, 접근 제한이 필요하다.

## 남은 작업

1. 검증 가능한 공급자별 BTC UTC 봉, FX 뉴욕 마감 및 주말·휴일, WTI 개별계약·거래일·롤을 수집하고 실제 원자료와 대조한다. 다른 상품이나 공급자로 대체할 때는 별도 사전등록이 필요하다.
2. 공급자 발표 원문과 수정 시각을 수집·검증하고 시점별 데이터로 기존 특성 생성과 모델 학습 전체를 다시 구축한다.
3. v0.5 장부에 별도로 만기 채점과 백업·복원 검사를 구현하고, 채점 시점의 데이터 출처·빈티지를 기록한다. 기존 v0.4 장부와 혼합하거나 사후 수정하지 않는다.
4. 자동 스케줄이나 외부 배포는 별도 승인 전 실행하지 않는다.
