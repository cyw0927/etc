# GMIA v0.4 사전 등록: 전진 검증 장부 (forward-test ledger)

**사전 등록 단계:** v0.4 장부 기록·채점 코드 작성 전, 이 문서를 별도 커밋으로 고정한다. 이 문서의 GitHub 커밋 시각을 방법론 등록 시점으로 사용한다. v0.2·v0.3에서 이미 사용한 과거 홀드아웃은 새로운 지지 근거로 재사용하지 않는다.

## 1. 목적과 이미 알려진 사실
- 2026-10-26~27에 평가한 v0.2·v0.3 백테스트와 홀드아웃은 **이미 확인한 데이터**다. v0.3에서 252개 검정 중 지지된 모델은 0개였다.
- 앞으로 발생할 예측을 그때그때 고정 기록하고, 관측된 결과가 나왔을 때만 채점한다.
- 실데이터가 충분히 쌓일 때까지 '검정 불가 / 표본 부족'으로 표시한다. v0.4 도입 자체가 성능 개선이라는 주장을 하지 않는다.
- 원래 모델의 확률이나 파라미터는 v0.4에서 변경하지 않는다.

## 2. 사전 고정된 후보 및 모집단
- 자산(9): `SPY, QQQ, KOSPI, NIKKEI, GOLD, BTC, USDKRW, USDJPY, WTI`
- 예측 기간(2): `5, 20`개 해당 자산의 봉. BTC는 달력일; 나머지는 각 시장 거래일.
- 모델(15): `baseline_base_rate, baseline_momentum, logistic_regression, hist_gradient_boosting, lightgbm, logistic_regression_shrink, logistic_regression_platt, hist_gradient_boosting_shrink, hist_gradient_boosting_platt, lightgbm_shrink, lightgbm_platt, h1_trend, h2_vol_regime, h3_rates_regime, h4_short_reversal`
- 기준모델: `baseline_base_rate` (B1). 나머지 14개 후보 × 9자산 × 2기간 = **252개 비교**.
- 모델 설정·선택·데이터의 갱신 방법은 v0.3 그대로. 이후 코드 수정으로 달라진 모델 예측도 기록하되 코드 커밋을 남기고 그 변경 이전/이후 표본을 구분하여 탐색적으로 보고한다. 등록된 가설의 성과 주장은 동일한 알고리즘 계열·예측 정의가 유지되는 경우에만 한다.

## 3. 예측 기록: append-only
- 실제 `run_all.py` 호출이 각 자산·기간에 대해 출력한 **모든 후보** 확률을 그 실행 당시 UTC 기록 시각으로 추가한다.
- 주요 필드: `recorded_utc, forecast_date, asset, horizon, model, probability, git_commit`. 추가로 `run_id, anchor_price, currency`를 감사용으로 기록한다.
- 기본 위치 `data/ledger/forward.sqlite3` (공개 저장소에 올리지 않음).
- 고유 식별자: `(forecast_date, asset, horizon, model)`. **첫 기록만 인정**하고 이후 재실행이 기존 값을 덮어쓰지 않는다.
- DB에는 신규 행 삽입만 허용한다. 이미 기록한 예측·채점은 UPDATE/DELETE 하지 않는다.
- 실제로 존재하고 완료된 봉을 기준으로 예측했는지 검증하며, 예측 타임스탬프가 없거나 확률이 [0,1] 밖이면 기록하지 않는다.
- 저장 실패를 성공으로 간주하지 않는다. 데이터 및 장부는 버전 관리에 포함하지 않는다.
- 주기적 자동실행은 현재 등록 범위가 아니다.

## 4. 채점의 만기·시점 규칙
- `forecast_date`의 해당 자산 봉에서 **정확히 h봉 뒤** 종료된 봉의 날짜가 만기일이다. 거래일/달력일을 임의로 더해 계산하지 않는다.
- T0 당시의 미래 가격을 이용하지 않는다. 채점 실행 시 확보된 **실제** 시장 원자료의 같은 수정종가 기준으로 `ret = adj_close[t+h] / adj_close[t] - 1`, `y = 1[ret > 0]`을 정의한다.
- 데이터가 없거나 수정종가가 0 이하·비정상이면 채점을 보류한다. 시장별 완료 시각과 +15분을 적용한다.
- **기록 시각이 만기 봉의 완료 시각 이상이면 사후 기록(late)이며 채점과 통계에서 영구적으로 제외**한다(기록 자체는 감사 목적으로 유지).
- 채점 시 참조한 원자료의 `fetched_at_utc`가 만기 봉 완료 시각보다 늦어야 한다. 그렇지 않으면 새 자료를 먼저 수집하도록 요구한다.
- 수익률과 정답도 append-only 채점 테이블에 첫 결과만 저장한다. 미래 공급자의 자료 수정 이후 과거 채점을 임의로 덮어쓰지 않는다.
- 시장별 원봉 날짜는 제공 시점·시장 마감 방식에 따라 완벽하게 재구성되지 않을 수 있으므로, 기록·채점 보수성을 우선하고 이 제약을 명시한다.

## 5. 검정 사전 등록
- 각 `(asset, horizon, candidate)`마다 B1과 **동일한 forecast_date에 기록되어 만기 채점된 쌍**만 비교한다.
- 표본 최소 조건: **최소 500개 만기·유효한 날짜 쌍**과 최초~최종 예측 기준일 간격 **최소 540일**(달력일). 둘 중 하나라도 미달하면 '표본 부족'으로 표시하고 지지 판정을 내리지 않는다. 이는 20봉 중첩으로 인한 유효 표본 수 감소를 완전히 해결하지 않으며 보수적으로 해석한다.
- 개별 손실 `d_t = (p_candidate - y_t)^2 - (p_B1 - y_t)^2` (음수가 후보에 유리).
- 표본 평균 차이의 표준오차는 Newey–West HAC/Bartlett, `lag=h`; H0: `E[d]>=0`, H1: `E[d]<0`, 단측 정규 근사 p.
- 전체 **고정 252개 비교**를 하나의 BH-FDR 집합으로 간주한다. 표본 부족·누락된 비교는 `p=1`로 보수적으로 처리해 다중비교 총수에서 제외하지 않는다. q=0.10.
- **'지지됨'** = (i) 최소 표본 조건 통과, (ii) 관측 평균 Brier 차이 < 0, (iii) 전체 252개에 대한 BH 조정 p ≤ 0.10. 이전 백테스트의 '검증 우위'를 추가 필터로 사용하지 않는다(재사용 홀드아웃에 의존하지 않기 위해).
- 개별 확률 보정(Brier) 및 B1 대비 유의성 외에 AUC·Log loss·누적수익률 등은 탐색적 참고치로만 표시한다.
- 날짜를 공유하는 여러 자산·후보의 검정은 서로 독립적이지 않다. BH 결과 역시 완전한 인과 증거가 아니며, FDR의 의존성 가정을 주의해 해석한다.

## 6. 금지 사항 및 예상 실패 처리
- 유의한 결과가 나올 때까지 최소 표본 수, q, 모델군, 기간이나 기준모델을 사후 변경하지 않는다.
- 스냅샷을 소급 삽입하거나 기존 예측의 날짜·확률을 수정하지 않는다.
- 기존 2024~26 홀드아웃의 성능을 v0.4 전진 성과로 표시하지 않는다.
- 최초 예측을 기록하기 전의 날짜에 대해 실데이터를 사후 실행한 예측은 forward-test로 집계하지 않는다.
- 실데이터 접근 실패, 장부 기록 실패, 모델 실행 실패는 명시적인 오류로 남긴다.
- 장부를 버전 관리할지 여부, PR #2 설명 갱신 여부, 자동 실행 여부는 사용자 결정 사항이다.

## 7. 구현 후 확인할 테스트
- 첫 예측 보존 및 중복 기록 방지
- UTC와 자산별 만기 시점 처리
- 만기 전 채점 금지, 오래된 데이터의 채점 금지
- 결과를 이미 알고 난 사후 기록 제외
- 기준모델과 후보의 같은 날짜 비교
- Brier 손실 차이 및 HAC/BH 정확성
- 최소 표본 미달 시 지지 불가
- 두 번째 채점에서 기존 결과 변경 방지

**주의:** 이 문서는 결과를 보기 전에 고정하는 선언이다. 이후의 발견은 별도 개선 문서에 기록한다.
