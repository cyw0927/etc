# 연구·예측·보정·전진검증

기존 v0.3/v0.4 사전등록은 수정하지 않는다. 5/20봉, 15후보(입력 없는 후보는 결측), 9자산, 252개 전진 비교, 대응쌍 500개·span 540일·HAC lag=h·BH q=.10은 유지한다. 이번에 새 후보·특징·예측기간을 평가하지 않는다.

## 기존 강점과 한계

학습구간 내부에서 전처리하고 시간순 분할·라벨 종료일 퍼징·내부 보정구간을 사용한다. 다른 시장은 날짜 strict join, 상관은 가격 수준 대신 수익률이다. 다만 날짜 strict는 release timestamp 검증을 대신하지 않는다. 원가격의 과거 조정, 전체기간을 보고 volume 피처 포함 여부를 결정하는 schema, 현재값 금리의 공개시점은 잔여 위험이다.

v0.2/v0.3의 알려진 2년 홀드아웃은 재사용됐다. 새 데이터로 재실행해도 그 역사 구간이 새 확증 표본이 되지 않는다. 미래값 주입 sanity test가 성공했다고 누출/구현 오류가 전혀 없다는 증거는 아니다. README의 기존 강한 표현은 이 한계를 함께 읽어야 한다.

h봉 라벨은 겹친다. HAC는 손실의 시계열 의존 일부를 다루지만 구조 변화·누락일·장기 의존과 자산간 검정 의존을 모두 해결하지 않는다. 252개 BH 결과 역시 독립 검정/적합한 의존성 전제를 검토해야 한다. 매일 누적 유의성을 들여다보는 반복검정은 별도 위험이며 확증 판정 시점/알파 지출 같은 향후 프로토콜을 새 사전등록으로 정한다. 현재 등록 임계값은 사후 조정하지 않는다.

## 다음 연구 규약

1. 경제적 질문·입력 source/빈티지·정보 cutoff·통화·캘린더·라벨·실패조건을 연구 ID와 새 사전등록 커밋에 고정한다.
2. 새 특징은 release 시각 기반 join을 통과해야 한다. 학습/보정/검증 경계마다 label end를 purge한다. 순방향만 학습하면 미래 train 블록 embargo는 필요 없지만, nested tuning/비순차 CV 도입 시 중첩 구간 제거와 embargo를 별도 명시한다.
3. 튜닝은 outer test와 분리된 nested 시간순 분할만 사용한다. 고정 B1/B2와 같거나 더 단순한 모델을 같이 보고한다. 레짐 정의·추정 파라미터도 학습 시점에서만 적합한다.
4. 1주/1개월/3개월, 수익률 분포·구간·tail risk는 별도 버전이다. 기존 5/20봉 성적과 섞지 않는다. 새 데이터/후보의 전진 실험군을 별도 ID로 관리한다.
5. 정확도만이 아니라 Brier/Logloss/보정곡선·ECE·AUC·예측구간 coverage/width를 본다. 전략 수익은 통화·비용·지연·노출·배당·현금금리의 별도 실험이다.

## 계량경제 연구 사다리

수익률/금리변화·단위 확인→롤링 30/90/180일 상관과 불확실성→동일 UTC cutoff/시차별 상관→공통 달러·금리·변동성 요인을 통제한 관계→레짐별 안정성→발표 이벤트 스터디 순서로 진행한다. 시차/자산/창을 많이 탐색할수록 다중비교 예산을 추가한다.

VAR/BVAR·동적 인자·상태공간은 충분한 표본과 release-aware ragged edge 처리가 확보될 때 사용한다. 변수 정상성/공적분·식별 가정·외생 충격·구조변화를 점검한다. Granger 예측 선행성은 인과성의 증명이 아니다. 더 큰 모델이 기준모델을 능가할 거라고 가정하지 않는다.

## 운영 평가 계약

발행 때 source/dataset/feature/model/config/environment/code hash와 seed, train cutoff, prediction time, horizon calendar를 고정한다. 데이터 drift(결측·분포·schema)와 성능 drift(만기 label 후 보정/Brier/coverage)를 구분한다. 드리프트 경보가 자동으로 새 모델 채택을 승인하지 않는다. challenger는 shadow ledger에서 시작한다.

현재 첫 forecast/score는 SQLite에 저장된다. 이번 triggers는 일반 UPDATE/DELETE를 막지만 DB 소유자의 schema 변경·REPLACE·파일 교체까지 막는 WORM이 아니다. 미래 운영에는 읽기 전용 UI 연결, INSERT 전용 role, 외부 hash anchor/객체잠금과 restore 훈련이 필요하다. 모델 변경 전후 표본은 탐색적으로 구분하며, 현재 통계 함수가 자동으로 알고리즘 버전을 분할하지 않는 점은 감사의 미해결 항목이다.
