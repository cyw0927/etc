# CLAUDE.md — GMIA 온보딩과 협업 지침

이 문서는 Claude/Claude Code 및 다른 AI가 이 프로젝트를 **한 번에 읽고 동일한 원칙으로 개발·분석**하기 위한 진입점이다.

## 현재 단계 (2026-10-28 갱신)
**v0.4 + 데이터 신뢰 기반: 불변 스냅샷·입력 추적·장부 보호·수동 백업. Windows 실데이터 수집/예측/만기 전 보류 확인; 실제 만기 채점은 대기.** 기존 v0.3 홀드아웃에서 지지된 후보는 0개. 사용자가 v0.1의 "코딩 금지·시뮬레이션 전용" 지침을 대체하고 실제 코드 작성·실행·검증을 지시했다.
- 목표는 그럴듯한 전망 서술이 아니라 **실제 데이터로 학습하고 자기 예측력을 미래 구간에서 검증하는 시스템**이다.
- 실거래·자동주문·매매 연동은 사용자가 명시적으로 요청하지 않는 한 구현하지 않는다.
- v0.1 원본 프롬프트(`prompts/01~03`)는 설계 참고자료로 **보존**한다. 수정하지 말 것.

## 재설계 인계

`docs/architecture/VISION.md`, `CURRENT_STATE_AUDIT.md`, `ROADMAP.md`, `VALIDATION.md`부터 읽는다. 기존 수치 성적과 새 검증을 구분한다. Source/PIT/시장/재무/사건/계량/예측/시나리오/감사/제품/운영 계층의 계약은 SYSTEM_ARCHITECTURE와 전문 문서에 있다. 새로운 계층 대부분은 설계이며 구현 완료로 보고하지 않는다.

새 source snapshot은 불변 파일+해시+원자 포인터다. 기존 형식은 legacy_unverified이며 source hash는 과거 발표시점 인증이 아니다. Availability 계약은 향후 어댑터용이고 기존 feature join에 통합되지 않았다. 장부 trigger는 일반 UPDATE/DELETE를 막지만 관리자 DDL/파일 교체를 방어하는 WORM은 아니다. 모델/평가기준은 바꾸지 않았다.

main 직접 push/force push 금지. PR #1/#2 및 PR #2 설명은 변경/병합하지 않는다. 이번 별도 브랜치는 #2 head에서 시작했다. 원자료·장부·백업·아티팩트·키는 커밋하지 않는다. 배포·과금·운영 스케줄 활성화는 별도 승인 전 금지한다. CI 검증은 허용된 코드 검사이며 운영 스케줄과 구분한다.

## 개발 규칙 (위반 금지)
1. **가짜 데이터 금지.** 데이터 수집이 실패하면 오류를 남기고 그 자산을 건너뛴다. 합성 데이터는 `tests/`에서만 쓴다.
2. **미래정보 유출 금지.** 특징변수는 예측 시점에 이미 관측 가능했던 값만 쓴다. 다른 시계열은 대상 날짜보다 엄격히 이전 값만 붙인다(`asof_strict`). 수정되는 거시지표는 발표 시점 빈티지 없이는 모델에 넣지 않는다.
3. **시간순 검증만.** 랜덤 분할 금지. 워크포워드 + 홀드아웃, 라벨 기간만큼 퍼징. 전처리(대체·표준화)는 학습 구간에서만 적합(Pipeline).
4. **항상 기준모델과 비교**하고, 나쁜 결과를 숨기거나 기간을 골라 좋아 보이게 하지 않는다. 홀드아웃 결과로 모델을 사후 선택하지 않는다.
4-1. **새 후보 모델·가설은 평가 전에 사전 등록**한다(`docs/preregistration_v*.md`, 커밋 시각이 등록 시점). 등록 후 결과를 보고 기준을 바꾸지 않는다. 최근 2년 홀드아웃은 v0.2·v0.3에서 이미 사용했으므로, 새 주장은 전진 검증 데이터로 판정한다.
5. **LLM은 확률을 만들지 않는다.** 상승확률은 통계모델 출력만 쓴다. LLM/뉴스 분석은 설명을 덧붙일 뿐 확률을 바꾸지 못한다.
6. 뉴스 점수는 과거 시점 기사로 백테스트할 수 있을 때까지 학습 변수로 쓰지 않는다.
7. 모든 예측에 데이터 기준일·학습기간·검증 성능·신뢰도를 표시한다. 실행하지 않은 테스트를 통과했다고 말하지 않는다.
8. 저장소는 **공개(public)**: `.env`, API 키, 데이터 파일(`data/`), 실행 산출물(`artifacts/`), 유료 기사 전문을 커밋하지 않는다.
9. 변경 후에는 `python -m pytest`와 `python scripts\run_all.py --no-fetch`를 실행해 확인한다. v0.4에서는 `python scripts\score_ledger.py`도 확인한다. 실제로 실행하지 않았다면 실행 검증 대기로 보고한다.
10. 전진 검증 장부는 `data/ledger/`에 보존한다. 첫 기록·첫 채점은 불변이며, 기준일·자산·h·모델 키로 중복 기록을 막는다. **사후 기록과 만기 이전 기록을 채점에 섞지 않는다.**
11. v0.4 `docs/preregistration_v0.4.md`에 등록된 252개 모델 비교, 최소 500쌍·540일, HAC/BH 검정 기준을 결과를 본 뒤 바꾸지 않는다.

## 분석 원칙 (v0.1에서 유지)
- 사실 / 당사국 주장 / 제3자 검증 / 추론을 구분한다. 동일 출처 반복 보도를 독립 확인으로 세지 않는다.
- 한국 언론의 국제뉴스 2차 보도는 기본 수집원에서 제외하되, 한국은행·통계청 등 공식 경제 원자료는 허용한다.
- 긍정·부정·모호함은 국가·산업·자산별로 판정한다.
- 자산가격 수준, 수익률, 금리(%), 금리 변동(%p), 환율 표기 방향을 혼동하지 않는다.
- PER/PBR 숫자만으로 저평가·고평가를 단정하지 않는다.
- 상관관계는 수익률로 계산하고 인과관계로 해석하지 않는다.
- AI 두 개가 합의했다는 사실만으로 정확성을 주장하지 않는다.
